# 页面与账号流程设计（审查稿 V1）

日期：2026-11-07。本文记录已确认方向及具体设计建议，不代表页面已经实现。

## 已确认事项

- 全站用户可见语言为简体中文：导航、按钮、校验、空状态、日期、通知、图表、导出列名均中文化。代码标识和接口字段保持英文。
- 视觉采用 Shadcn Admin 的简洁布局，结合克制的蓝色配色；基础框架候选为 Pure Admin 精简版。尚未导入模板或变更依赖。
- 登录采用账号与密码，提供注册和找回密码入口。
- 注册者只能申请员工身份，管理员审核后启用。
- 找回密码由管理员核实身份后协助重置，不接入邮件或短信。
- 本方负责 F01—F08；同学模块只做文字和接口说明，不实现具体页面和业务。

| 按钮层级 | 每个区域一个主要操作；删除、停用与发布需确认影响 |

配色是实现建议，交付时检查文字对比度、键盘焦点与状态可辨识性。表格内容密集处减少阴影，保持行列对齐。

## 页面骨架

桌面端：约 224px 浅色侧栏 + 64px 顶栏 + 内容区。排班工作台按需要展开约 340px 右侧详情抽屉。小屏收起侧栏，员工班表使用按日列表；管理者周班表允许横向滚动。

管理者导航：工作概览、排班工作台、人员与技能、班次与需求、时间与偏好、排班规则、账号审核、历史版本。动态调班、业务审批、通知、统计和日志为同学模块，接入前不伪装成功页面。

员工导航：我的班表、时间与偏好、个人中心；后续由同学加入我的申请、换班邀请及通知。账号审核属于 F01，由本方实现，与同学负责的请假换班审批分开。

排班工作台：顶部周期选择、草稿/已发布标签及版本号；中部少量必要指标；主区域为日期 × 早中晚班网格，每格按岗位列出人员和缺口。右侧用于班次详情、候选人员、冲突定位；智能解释面板仅预留契约说明。

## 账号页面与流程

### 登录

居中登录卡片，字段为账号、密码，支持显示/隐藏密码；底部为注册账号、忘记密码。页面标题使用“智能排班与动态调班系统”。不提供第三方登录、手机号登录或多种认证入口。

正确密码但尚未审核的用户只能得到受限的“等待审核”页面及退出入口，不能访问业务数据；被拒绝的注册可查看审核说明。错误凭据返回统一中文提示。

### 注册

字段：账号、姓名、密码、确认密码。账号建议限定为 4—32 位字母、数字、下划线，规范化为小写；密码初版建议 12—128 字符，允许粘贴和密码管理器。具体规则保持前后端一致。

客户端不提交角色或审批状态。服务器固定角色为员工、状态为待审核。注册成功后显示等待审核说明，不进入排班页面。

管理员审核时选择：创建新员工档案，或绑定已有未绑定账号的员工档案；避免员工被提前录入后又重复注册档案。审批通过才建立有效绑定和业务权限。已绑定档案不能再绑定其他账号。

第一位管理员通过未来初始化流程建立，由本地配置提供初始密码并强制修改；公共注册不能生成管理员。不得内置固定管理员密码。

### 找回密码

“忘记密码”页面说明联系门店管理员。用户填写账号并提交重置申请后，统一显示“如账号有效，管理员将核实并协助处理”，不返回账号是否存在。

管理员在账号管理页查看申请，在线下核实本人身份后执行重置；仅凭申请本身不构成身份核验。生成随机临时密码，通过核实后的线下渠道交给本人，页面仅展示一次，不写入日志或通知内容。临时密码建议 24 小时有效。

用户用临时密码登录后仅可修改密码或退出，修改成功才进入业务系统。重置和修改密码均撤销此前会话。重复申请限频、合并待处理项；不存在账号不生成真实账号记录。

管理员遗失密码由另一管理员协助；只有一个管理员时，后续提供本机受控恢复操作方案，不提供公开绕过入口。本期仅设计，恢复工具待账号开发阶段实现。

## 通用交互

- 错误信息说明原因及下一步，不能直接展示数据库或 Python 异常。
- 无数据、未提交、计算中、计算失败和无可行解是不同状态。
- 保存草稿与发布明确区分；允许有冲突草稿，禁止有硬冲突的发布。
- 已发布后修改创建新草稿，不直接覆盖原版本。
- 密码字段、请假原因等不出现在无关列表、日志和跨角色响应中。
- 日期使用“2026年11月9日 / 周一”，时间使用 24 小时制；前端明确 Asia/Shanghai。

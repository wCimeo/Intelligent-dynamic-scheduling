## 当前实现范围

- Vue 3 / TypeScript / Element Plus / Vite；全中文，浅色蓝色工作台，中文组件语言。
- 登录、注册待审核、管理者审核（新建或绑定员工）、会话退出、首次改密、个人密码修改。
- 找回密码申请写入数据库；管理员可在“密码重置审批”页面查看待处理申请、填写身份核实说明并生成一次性临时密码。重置会递增账号版本、撤销旧会话，并强制用户首次登录改密。
- 管理员可创建已启用员工账号，可选绑定未使用的员工档案；账号支持状态筛选、停用和启用，停用立即撤销会话，并保护最后一个有效管理员。
- 员工目录支持查询、搜索、状态/岗位筛选、新建、编辑、停用和技能维护；岗位与技能字典、岗位技能要求及员工可胜任岗位计算已实现。
- 班次模板支持时间和默认岗位人数；排班周期可生成本周草稿、跨周复制、关闭单日/单班次并调整岗位人数，保存完整输入快照与周需求指标。
- 员工可维护常规周可用时间、日期替换/扣除例外和按周期提交希望/避开偏好；管理员可查看填报进度与员工实际可用时间，并通过受审计接口代录。
- 排班规则采用不可变版本，硬约束包含每日/每周工时、连续天数和班间休息，软约束包含偏好、工时均衡和晚班均衡权重。
- CP-SAT 求解任务固定输入快照，检查技能、可用时间、岗位覆盖和时间/工时规则，并按规则权重优化偏好与公平性；任务状态和结果可轮询查看。
- 班表工作台支持按员工/岗位筛选、点击增删人员、锁定指定安排、统一冲突校验，并显示覆盖、工时和偏好指标。
- 发布采用短事务和 revision/输入指纹校验，自动替代旧版本、写审计与领域事件；历史版本可恢复为草稿，员工可查看当前已发布班表中的本人安排。
- F14后台消费者处理发布、请假、换班事件；发布只通知受影响员工并生成版本确认回执，通知失败可重试且不撤销业务。
- F11可从真实缺岗事件生成最多3个最小改动方案，支持锁定范围、指标比较、过期校验和应用发布。
- F15按当前发布版本统计计划工时、班次、晚班、缺口、偏好和确认，并导出经过公式注入防护的CSV。
- F16提供单门店设置、默认求解时限、审计查询和前端门店名称联动，时区固定为Asia/Shanghai。
- F12由员工输入自然语言，后端调用DeepSeek并严格校验结构化JSON；结果先进入`PENDING_CONFIRMATION`，员工可修改日期例外、时段、班次、偏好类型和权重，确认后才写入可用时间与偏好草稿。
- F12失败、超时、额度耗尽或格式错误时不写业务数据，并提供“前往时间与偏好”的手工回退；密钥仅在服务端读取，调用限额和输出token边界可配置。
- F13管理者可解释当前发布班表或动态调班候选，员工只能解释本人已发布安排；后端在调用模型前完成角色过滤，不把其他员工安排、请假原因或管理字段传给员工侧解释。

## 架构、数据与安全边界

- 参考既有模板的视觉组织，使用 Element Plus 现成组件搭建轻量骨架；没有复制 Pure Admin 整仓或声称完成模板迁移。
- 会话哈希采用 SHA-256 的64位十六进制字符串存储（VARCHAR(64)），与设计中的 BINARY(32) 等价容量含义但表示不同。
- 数据库按阶段新增迁移0001—0015：账号、员工、岗位技能、班次需求、可用时间、规则、求解、发布、outbox、请假、换班、通知确认、调班候选、门店设置、AI解析记录和AI解释记录。
- 本项目 ID 使用有符号 BIGINT，API 输出字符串；所有阶段沿用同类型外键，没有重写历史迁移。
- SQLite用于流程与边界测试；关键迁移、事务、外键和回滚另通过真实 MySQL 验证。
- 当前仅单 API 进程；内存限频不是多实例生产限流。没有暴露公网或进行部署。
- F12不把模型结果直接写入业务表；确认请求重新校验日期范围、重复项、版本和当前业务事实。F13对模型输入先做角色裁剪，员工解释只包含本人数据。
- 密码重置使用 Idempotency-Key、expected_revision 和事务内行锁；临时密码明文不写入数据库、审计或幂等记录，重复请求不再显示。

## F08 发布、版本与差异补充（2026-11-08）

- 数据库迁移 0008 新增 scheduling_guard、outbox_events，并为 schedule_periods.current_version_id 增加发布版本外键；本机 MySQL 已升级至 0008 (head)。
- 发布事务锁定 guard、周期和草稿，校验草稿/周期 revision、基准版本和当前输入指纹，再使用最新事实执行统一硬冲突校验。
- 同一周期只保留一个 PUBLISHED 版本，旧发布版本标记 SUPERSEDED；周期指针、版本发布时间/发布人、审计和 `schedule.published` outbox 同一事务提交。
- 已经开始或结束的班次及人员安排不能在新版本中改写；历史恢复生成新 DRAFT，并继承当前发布版本中已开始部分。草稿可废弃，发布版本只读。

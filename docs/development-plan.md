创建目录，迁移完整设计，记录合作方式、开发计划和接口预留清单。不安装依赖、不初始化应用、不进行仓库操作。

## 阶段 1：详细设计与技术基线

已核验本机 Node、MySQL 服务握手，并创建 schedule（Python 3.12.16），安装验证核心 Python 依赖。技术基线采用 Vue 3 + TypeScript、FastAPI、MySQL 8.0、OR-Tools；前端依赖、数据库认证及项目库迁移已完成核验，当前进度详见 framework-status.md。详见 technical-baseline.md。

产出实体关系图、F01—F08 字段级数据字典、状态与错误码约定、主要页面结构及接口契约。对 F09—F16 仅描述数据边界和扩展点；需要共同决定的表结构先形成设计约定，避免替同学实现功能。

## 阶段 2：最小可运行框架与首次交接

初始化前后端应用，建立配置加载、数据库连接与迁移、认证权限基础、统一错误处理、前端布局和路由、健康检查。提供本地配置示例，不包含真实密钥。

完成可登录的管理者与员工账号、最小员工数据查询和演示种子数据。补齐安装、启动、迁移、测试命令。

验收：按 README 在本地启动前后端、初始化数据库、登录并查看基础页面。此时即可向同学交接并开始并行开发。

## 阶段 3：基础业务 F01—F05

依次完善账号权限、人员与技能、班次和岗位需求、可用时间与偏好、规则配置。每项包含页面、接口、数据校验和适当测试。

验收：可通过界面录入一套完整的周排班输入；员工权限隔离有效；规则版本与时间优先级明确。

## 阶段 4：排班闭环 F06—F08

先实现统一规则校验器和基础求解器，再接入异步任务、班表草稿与手工编辑，最后实现发布事务、并发版本控制、历史快照与差异查看。

测试覆盖技能、岗位人数、时间、工时、跨周休息与连续工作日；区分可行解、已证明无解和超时未知。只读历史版本，恢复历史时生成新草稿重新校验。

验收：从基础输入到生成、编辑、校验、发布和版本比较完整可用；两次并发发布不会互相覆盖。

## 阶段 5：对接稳定与本方交付

稳定供同学调用的基础服务和扩展契约，提供请求响应样例及模块级调用示例；示例不代替同学业务实现。通过注入测试输入验证额外不可用时间、基准版本过期和发布事件等对接边界。

整理已实现清单、测试结果、数据库迁移、演示数据、已知限制和启动说明。与同学联调时修复本方问题，同学范围问题记录并交由其处理。

## 交付边界
